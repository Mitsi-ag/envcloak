Binding undo extends `ref` with private inherited descriptors. It captures the
actual successful writer input, checks directory identity and exact after
bytes, and restores original comments, CRLF, inline and dotted syntax. Only the
selected binding may differ semantically. Failed/no-op edits do not advertise
an undo receipt. Failed or uncertain restoration consumes the receipt and
refreshes the project instead of claiming success. The system UndoManager holds
an action identifier, while private source bytes stay in `SecretBuffer`.

Contract follow-up `c731a2ab` reuses the reserved `io` exit token and makes
private descriptor parse failures statically readable. Its four ref unit
checks pass; the descriptor mutation is recorded in `061fd376`. Drag entry
and the selected binding also stay within the secret-key picker.

The cycle536 binding-undo contract is the independent oracle: original fixture
bytes, actual writer input, directory identity, stale after state, LIFO and
failure publication are checked independently of the serializer.

## Third CI follow-up, 9 October 2026

Run `37799032726` identifies the failure before paste: the CLI reports
`references: null`, `unchecked: daemon_unverified`, exit 1. The cause is
the UI test runner's inherited App Sandbox. The job log's
`ProcessProductPackaging` output at lines 7328 to 7358 signs the runner with
`com.apple.security.app-sandbox = true`, despite the project's
`ENABLE_APP_SANDBOX = NO`. Reading the local Xcode 26.6 runner with
`codesign -d --entitlements - --xml` independently confirms the same setting.
[Apple DTS describes this separate sandboxed UI runner](https://developer.apple.com/forums/thread/740051).

The connection trace is:

- `envcloak-client/src/connect.rs` calls `RunPaths::for_user`. On macOS,
  `envcloak-ipc/src/paths.rs` derives
  `$HOME/Library/Application Support/EnvCloak/run/envcloakd.sock`.
  `XDG_RUNTIME_DIR`, `XDG_STATE_HOME`, `TMPDIR` and
  `ENVCLOAK_TEST_RUNTIME` do not choose the CLI socket on this platform.
  The last variable is a Swift screen-test override, not a CLI override.
- `Client::connect_as` checks the runtime directory, its parent and the
  socket's type and ownership, connects, then requires `getpeereid` to
  report the same uid before sending any request. This branch pins no
  daemon signing identity. Its informational `DaemonIdentity::Unverified`
  is distinct from a failed connection's `daemon_unverified` error token.
  Neither the daemon's executable path nor its signature selects this peer.
- The fixture explicitly runs lane D's debug daemon under its private HOME.
  The installed helper from `build-app.sh --install` serves another HOME;
  no PATH search or installed-binary comparison participates in this check.
  `/tmp` and `/private/tmp` name the same fixture directory. Canonicalizing
  the manifest explains `/private/tmp` in the report and does not change
  the socket selected from HOME.
- Foundation `Process` starts the check CLI inside the runner's sandbox.
  On the measured host, `appsandbox-common.sb` grants `network.client`
  outbound IP access; `application.sb` separately permits Unix sockets in
  the container or approved locations. The fixture socket is outside them.
  The runner's read-only file exception allows metadata reads, not that
  connection. Permission denial from `connect_unix` maps to
  `Unverified::Socket(Io(...))`, then `daemon_unverified`; `check` correctly
  returns 1. No product verification or success condition was changed.
