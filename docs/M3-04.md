# M3-04: project metadata and removing bindings

Scope: client-role `projects.list`, `envcloak ref --unset`, typed Rust client
and output shapes, IPC reservations, and manifest documentation. Requirements
R-M3-F1 and the Projects data portion of R-M3-03 are implemented here. The
Projects UI remains M3-05; editing and undo in the app remain M3-06.

The supplied M3 plan has no Review log or separate Founder decisions section.
Its D3-17/Q3-04 default permits project metadata for any client. Its §5 adopts
M2 plan §6, whose common rules and founder decisions were also read. SPEC §5
Items, §6.4 Adoption and §15.2 gates 12, 13 and 17 govern this implementation.

## Behavior

- Pages use the verified vault index, descending `(last_seen, id)`, with an
  exclusive cursor and a 768 KiB encoded-result budget. Unknown fields and
  malformed cursors fail without echoing input. Every page checks lock and
  integrity state. Metadata reads do not reset the idle timer, like `items.list`.
- The baseline had no production writer of `Vault::upsert_project`. The covered
  run path now records its effective manifest-sourced bindings, manifest hash and last-seen time
  after framing and grant validation, as a provisional transaction. Grant
  lifetime and root liveness are checked again after staging, then the delivery
  is durably audited before the transaction commits. A final check follows
  the commit, anchor and manifest-change audit. An audit failure or lapse rolls
  back or restores the row; a failed index write releases nothing and leaves
  the grant unused. The existing failure paths and delivery gates still run.
- Index entries describe the last adopted run's effective manifest and selected
  profile bindings. Ad-hoc refs, env-file names and bindings they override are
  excluded. A covered subsequent run replaces that metadata, including a changed manifest hash. A listing is not a snapshot:
  a new adoption above its cursor is visible on refresh.
- Unset removes the selected source span without serializing the document.
  Comments, quoting, line endings, other bindings and policy remain unchanged.
  Inline env tables lose only the member and one comma separator. The editor
  validates the resulting manifest and shares the atomic write path with set.
- The write stamp now includes ctime as well as device, inode, size and mtime.
  Symlinks and hard links are refused, staging is synced, the stamp is checked
  before rename, and the parent is synced. An I/O failure does not claim that a
  replacement could not already have happened.
- An absent binding exits 1 with `binding_absent` and no write. Successful JSON
  contains exactly `profile`, `env_name`, `reference`. Value-shaped argv is
  refused before any file read, without echo. New input-bearing wire types and
  command arguments have value-free Debug implementations.

## Third review: boundary repairs

The tampered gate holds through two layers: `State::unlocked` checks integrity,
and `Vault::projects` independently calls `trusted()`. The socket test checks
that combination, not the daemon guard alone. V1 removes only the daemon guard
and survives as expected; P1's empty-success mutation remains the negative
control for the externally visible contract.

The latest findings are accepted except the dotted-inline profile claim. The
reported `env = { ci.DROP = 'x', KEEP = 'y' }` is valid TOML but is not a valid
EnvCloak manifest. `manifest::env` treats an inline table as a binding;
MANIFEST.md explicitly says inline env tables contain bindings only. The
reported example fails with `manifest_invalid` / `unknown key` before the
editor reaches source-span removal. The independent Python oracle now parses
seven such examples with `tomllib`, then requires that exact EnvCloak refusal,
empty stdout, unchanged inode/bytes/mode and no staging file. Existing valid
standard/dotted profile and inline-binding edits still have positive controls.
No manifest grammar expansion is part of M3-04.

The sweep revisited every task path listed above, plus the newly changed core
project encoder limits, vault API tests and VAULT.md. No other instance of these
classes was found among the task's production changes. The cycle530 adoption
checkpoint review informed the finalization cases; its JSON is a proposed
contract, not an executed oracle. This lane's tests execute the real vault,

A project index records admission to delivery, not socket receipt or command
startup. Compensation is a separate durable transaction; permanent storage
failure can prevent it. In that case no answer is released and the daemon
quarantines the vault. Its on-disk index requires repair before restarting it;
this change does not claim crash-atomicity between an external socket release
and SQLite metadata.
