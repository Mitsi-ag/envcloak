## Independent checks and limits

The indexed `cycle529` projects review distinguishes adopted bindings from a
current manifest and from delivery evidence. Labels preserve that distinction,
and current `items.check` results have a separate filesystem change signal.
`projects.list` pages publish atomically: repeated cursors, duplicate folders,
more than 100,000 records, more than 16 MiB or more than 30 seconds fail without
a partial inventory. Each individual request also has the client's deadline.

FakeDaemon scripts traverse the actual framed socket client. The UI story
uses the real Rust CLI and daemon, creates an adopted project and positive
grant control, navigates with Command-1 and Command-2, opens the project and
revokes the grant. A separate Python RPC client checks `grants.list` after
XCUITest. Escape checks additionally run the M3-03 Python and Rust oracles.

No personal vault, credentials or runtime directory is used by these tests.
The detached local runner clears the environment, gives the fixture short
HOME/XDG paths and reaps only owned child handles. Generated test values stay
in the private fixture; logs do not print them. Fixtures are kept for diagnosis.
The CI wrapper applies the same isolation. The explicit screen-test compile
flag is excluded from normal builds and is a compile error in Release.
UI automation positions only its test window on the primary screen, capped
at 1024 by 700 points and fitted to the usable display, so restored window
geometry cannot place its controls off screen.
The fixture uses a saved alias for navigation, canonical daemon grant paths,
and ASCII generated values before wire encoding. PTY cleanup preserves the real test exit status. The detached
launcher reserves a fresh log name before forking and refuses reused receipts.

Only user-added folder paths and the selected adopted scope path persist. A persistence failure reports failure;
it does not claim a folder was saved. Terminal buttons open the fixed Terminal
application and copy quoted commands. They never open an untrusted folder
path as a Terminal document, which could execute a replaced `.command` file.
Binding access labels describe recorded grants for a variable and key.
`grants.list` does not report the approved field or manifest digest, so those
labels do not promise coverage of the next run's profile, fields or command.
