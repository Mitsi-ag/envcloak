## Independent checks and limits

The indexed `cycle529` projects review distinguishes adopted bindings from a
current manifest and from delivery evidence. Labels preserve that distinction,
and current `items.check` results have a separate filesystem change signal.
`projects.list` pages publish atomically: repeated cursors, duplicate folders,
more than 100,000 records, more than 16 MiB or more than 30 seconds fail without
a partial inventory. Each individual request also has the client's deadline.

FakeDaemon scripts traverse the actual framed socket client. The UI story
uses the real Rust CLI and daemon, creates an adopted project and positive
grant control, navigates with Command-1 and Command-2, opens the project and
revokes the grant. A separate Python RPC client checks `grants.list` after
XCUITest. Escape checks additionally run the M3-03 Python and Rust oracles.

No personal vault, credentials or runtime directory is used by these tests.
The detached local runner clears the environment, gives the fixture short
HOME/XDG paths and reaps only owned child handles. Generated test values stay
in the private fixture; logs do not print them. Fixtures are kept for diagnosis.
The CI wrapper applies the same isolation. The explicit screen-test compile
flag is excluded from normal builds and is a compile error in Release.
UI automation positions only its test window on the primary screen, at a
fixed size, so restored window geometry cannot affect mouse input.
The fixture uses canonical project paths and ASCII generated values before
wire encoding. PTY cleanup preserves the real test exit status. The detached
launcher reserves a fresh log name before forking and refuses reused receipts.

Only user-added folder paths persist. A persistence failure reports failure;
it does not claim a folder was saved. Terminal buttons open the fixed Terminal
application and copy quoted commands. They never open an untrusted folder
path as a Terminal document, which could execute a replaced `.command` file.
Binding access labels describe recorded grants for a variable and key.
`grants.list` does not report the approved field or manifest digest, so those
labels do not promise coverage of the next run's profile, fields or command.

## PR 44 package scheme correction

Adding the `EnvCloakKitTestSupport` library product made Xcode generate a
separate `EnvCloakKit-Package` scheme containing the package tests. The
`EnvCloakKit` product scheme has no test action. CI now selects each package's
test scheme explicitly; Design continues to use `EnvCloakDesign`. Both
commands retain warnings as errors and their compiled-source inventories.

The original CI command reproduced exit 66 before the change. The named
mutation `select-product-scheme`, applied to a copy of the corrected CI step,
again selected `EnvCloakKit` and failed with the same diagnostic and exit 66
(`m305-ci-product-scheme-mutation.log`). With `EnvCloakKit-Package`, Xcode ran
38 tests with zero failures and four explicit fixture-dependent skips
(`m305-ci-package-tests.log`). The dedicated isolated Kit runner then passed
all 38 tests without skips, plus both optimized wipe tests and the independent
oracles (`m305-ci-checks.log`).

Both new package build inventories passed. Design's compiled XCTest bundle
passed all eight tests when invoked directly with `xcrun xctest`, including
the assetutil check of the compiled color catalog (`m305-ci-design-direct.log`).
The combined `xcodebuild` run is not a pass: its Design invocation built but
started no tests for five minutes. Only that owned invocation was interrupted;
it exited 75 (`m305-ci-package-tests.log`, `m305-ci-design-timeout.txt`). No
shared test service or another lane's process was reset. This does not close
the earlier final-head UI automation acceptance check.

The CI inventory tests, fmt, strict workspace/all-target Clippy, unsafe,
expose, Swift rules, reservations, SPEC decisions and crate graph checks all
