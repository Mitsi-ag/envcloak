# M3-07: native peer identity

Scope: R-M3-15, R-M3-16 (Rust/CLI half), R-M3-41; M3 g1 (Rust directions), g4, and gates 19, 20, 21 and 22. The Swift daemon check and pins equality belong to M3-10. Developer-profile QA A14/A15 belongs to M3-21. App unlock and approval handlers remain reserved for their respective tasks.

## Build and trust boundary

`envcloak-sys/src/peer_code/pins.rs` holds the three signing identifiers and holds a literal `TEAM_ID` set before compilation. A signed build sets that public Team ID in the source file before building both Rust binaries. Source builds omit it and remain unverified, with no app role. A malformed configured pin fails closed. There is no runtime variable or flag to disable an embedded requirement. The founder's actual Q3-01 Team ID remains to be supplied; no machine credentials or production identity were inspected for this task. `build-app.sh --sign development` and `--sign ci` now run the release-compiled `production_pin` preflight and refuse before signing or creating output until a production requirement is configured. Ad hoc source builds remain explicitly unverified. Developer ID packaging stays M7.

`peer_satisfies(token, peer, pin)` first binds the exact token to the recorded peer's uid, pid and pidversion, then uses that complete token with Security.framework's dynamic guest lookup and requirement check. A signature verdict for B cannot authorize A even when socket users alternate A -> B -> A between separate identity reads. It reads both static and dynamic runtime flags and rejects the presence of debugger or runtime exception entitlements, including false-valued ones. API and metadata failures deny. The daemon caches admission only in one accepted connection; `peer_unchanged` compares uid, pid and exec generation before dispatch, and admission rechecks it after the signature work. App evidence is gathered per request, with claims able only to tighten. Agent evidence and cut chains refuse everything except the reserved `app.lock`.

The Rust client checks the daemon before encoding or sending a request, binds the successful check to the peer instance and checks it again before a request and after a response or transport failure. A late identity loss reports uncertain delivery and permanently invalidates the connection. Vault creation preserves the Recovery Kit after this failure because the request may already have taken effect. `Client::identity` describes that connection. The existing CLI status formatter uses it for text and JSON; the daemon does not vouch for itself in its status payload.

## Native harness

Run `scripts/macos/check-peer-code.sh` outside a recognized agent's ancestry. It creates two disposable identities in explicit temporary keychains under the target directory, compiles the certificate fingerprint only under `testing`, builds the current tree and runs both Rust integration targets with `--no-fail-fast --test-threads 3`. Ordinary crate runs report these native targets as ignored with the runner named. CI runs the native runner explicitly.

On this host `codesign` would not select an untrusted fixture identity. The test-only Objective-C signer in `envcloak-sys/tests/fixtures` passes the identity from its explicit keychain directly to Security.framework's signing SPI. This keeps the account's trust settings unchanged. The SPI is used only to generate test artifacts, never linked into Cargo or the product. Real signature checks use the public dynamic APIs. `codesign` and the independent Swift `SecStaticCode` reader inspect the resulting artifacts.

Apple silicon requires a signature on arm64 executables. The genuinely unsigned fixture is x86_64 and runs through Rosetta on arm64. The runner requires this capability and fails if the fixture cannot execute; an OS refusal is not counted as a daemon refusal. Every fixture has a cleared environment and a short isolated HOME/XDG tree. Frame responses are synchronization barriers. Child cleanup uses owned process handles, and no production certificate, keychain or trust setting is selected.

## Independent checks and dependencies

The provided oracle index's cycle431 signing-policy report qualifies modeled metadata checks only, explicitly not native peer validation. Its existing `test_sign_check_policy.py` suite is retained as a separate policy check. Native fixture properties are read through `scripts/macos/tests/oracles/codesign_facts.swift`, independently of the Rust code, with real signed positive controls and a DYLD constructor control.

The added macOS dependency tree is identical for aarch64-apple-darwin and x86_64-apple-darwin: security-framework 3.5.1, security-framework-sys 2.17.0, core-foundation 0.10.1 and core-foundation-sys 0.8.7, plus existing libc and bitflags. No new proc-macro dependency was added. The review repair adds one explicitly reviewed, dependency-free `envcloak-sys/build.rs`, pinned by `security/sys-build-script.sha256` in `check-unsafe.sh`. It runs no tools, generates no Rust and cannot supply a test pin without `testing`. It checks [Cargo's `PROFILE`](https://doc.rust-lang.org/cargo/reference/environment-variables.html#environment-variables-cargo-sets-for-build-scripts) independently of `debug_assertions`, rejects testing in release profiles, validates the public fixture fingerprint and emits only a compile-time constant. Cargo tracks the fingerprint input, so clearing or changing it rebuilds the dependent code. The runner never modifies tracked source; concurrent builds and SIGKILL cannot leave a substituted pin behind. The compiled-source check resolves the compiler dependency file for Cargo's custom-build artifact in both profiles and checks every file it read. The reservation checker permits this one bounded input only with that reviewed hash; it cannot become an exit token, and moving it to another source file is refused. Signing checks refuse test-support markers in every executable, even an ad hoc artifact. The raw signing-information call is confined to envcloak-sys with ownership and SAFETY comments.

API references: [Apple guest lookup](https://developer.apple.com/documentation/security/seccodecopyguestwithattributes(_:_:_:_:)), [audit-token attribute](https://developer.apple.com/documentation/security/ksecguestattributeaudit), and [Apple signing SPI source for the fixture generator](https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_codesigning/lib/SecCodeSigner.h).
