# EnvCloak: M1 acceptance

Status: M1, and the start of M2. This file says how the M1 acceptance story (SPEC §15.1) and every M1 gate (SPEC §15.2, gates 1 to 33) are tested, and where; the last section is M2's harness: the pinned agent hosts, the scripted model they are driven with, the store sweep and story step S0 (M2 plan task M2-04). M1 is done when the story and every gate pass on `macos-latest` and `ubuntu-latest` in CI (`.github/workflows/ci.yml`). The story's code is in `crates/envcloak-e2e/`.

## The story

`crates/envcloak-e2e/tests/fixture_story.rs` runs the story as one ordered test, on the built `envcloak` and `envcloakd`, in one isolated user: `HOME` and every `XDG_*` directory under a short `/tmp/ecXXXXXX` (so the socket path stays under macOS's 104-byte `sun_path`), a cleared environment for every process, and `envcloakd --foreground` started by absolute path.

- **The person** runs each command leading a session on a pseudo-terminal of its own, as in a terminal window, with no agent in its ancestry. What a command asks for on the terminal is typed when its prompt shows, waiting for the prompt's text, never for a time. Secrets on descriptors (`--passphrase-fd`, `--kit-fd`) come from files outside the home.
- **The agent** is `fixture-agent` (crates/envcloak-testkit), which the builtin catalog knows, running one shell for the whole story, with no terminal. A grant is scoped to that process instance, so it covers the agent's later commands.
- **The fixture repo** `acme-web` is generated at run time from `envcloak-testkit`'s canaries: `OPENAI_API_KEY` (an `sk-proj-` prefix, 64 bytes), `STRIPE_SECRET_KEY`, `GITHUB_TOKEN`, `DATABASE_URL` (a password with `/`, `"`, `+`, a space and a non-ASCII character), `SHORT_TOKEN` (10 bytes, in `.env.short`, so in the `short` profile only), `PORT=8080`, and a `.env.example`. No key-shaped literal is in the source.
- **Its command** `./emit` (`crates/envcloak-e2e/tests/fixtures/emitters/emit.py`) puts each value through every serializer gate 8 names: Python's `json.dumps` (`ensure_ascii` true and false), `quote` and `quote_plus` in upper and lower hex, form encoding, standard and URL-safe base64, padded and unpadded, at offsets 0, 1 and 2 of a larger payload, and lower and upper hex; Node's `JSON.stringify` (`emit.js`), Go's `encoding/json` (`emit.go`), .NET's `System.Text.Json` (`Emit.cs`), PHP's `json_encode` (`emit.php`) and serde_json (`ec-emit-serde`). Each result is written whole and in pieces, on standard output and standard error at once: every byte boundary of `DATABASE_URL`'s results, three boundaries of the others', with a 45 ms pause after each piece (the runner flushes after 40 ms idle), then bytes that are not UTF-8 around halves of a value. Last, each serializer prints the SHA-256 of each value it was given.
- **The sweep** runs after every step: everything any process printed, every daemon's log (the one S11 stops too), and the whole home with the fixture repo in it, for every canary (the values, the passphrases, a wrong passphrase typed once, the Recovery Kit) in every encoding `envcloak-testkit` knows, and for what each serializer made of each value, run outside EnvCloak before the story starts and loaded as bytes. Only the fixture repo's `.env` files are skipped, until S2 takes their secrets out.

## Gate 12

`crates/envcloak-e2e/tests/gate12.rs`, with `RUST_LOG=trace` and `RUST_BACKTRACE=full` in every process:

- **Injected panics.** Both binaries print a panic's place in the source and never its message (`envcloak_sys::install_panic_hook`), and no backtrace. `envcloak internal panic` and `envcloakd internal panic` panic with what standard input holds, in every build. The test build also panics on request at places on a value path (`envcloak_sys::panic_point`, feature `testing`, which no release build has): the CLI holding a run's released values (`cli.run.released`), the CLI holding an env file's parsed values (`cli.import.parsed`), and the daemon about to send a run's values (`daemon.release`). Each message holds a fixture; none shows anywhere.
- **Malformed inputs holding fixtures.** Values on the command line wherever a name or an id goes, and in an argument that is not UTF-8; a manifest with a value where a reference goes, one that is not TOML, and one with a value as a variable name; env files whose broken lines hold values, for `init`, `import --scan`, `check` and `run --env-file`; a value where the Recovery Kit or a passphrase goes, and a value with a NUL byte on standard input; frames sent straight to the daemon's socket with a value as the method, as an unknown field, JSON-escaped where base64 goes, as a slug, in a request's paths and names, as the whole body, and after an oversized header.

CI also runs the whole workspace's suite at `RUST_LOG=trace` and `RUST_BACKTRACE=full`, and `TestHome` passes both settings on to every process the tests start (they choose what a program logs and hold no secret). No EnvCloak program reads `RUST_LOG` yet: M1 has no logger, and the daemon's log is the fixed lines it writes to standard error. The setting is kept so that logging added later runs at its most verbose under the same sweeps. Gate 12 rests on `gate12.rs`, the fixture story (swept after every step), and the sweeps of the tests that start processes with fixtures, each of which sweeps the streams and logs it captures, among them the service-managed daemon's log in `crates/envcloak-cli/tests/service.rs`.

## Running it

`cargo test --workspace` runs everything. The story needs `python3` (it drives the terminals), and uses whichever of `node`, `go`, `dotnet` and `php` are on `PATH`, building the Go and .NET emitters under the target directory; set `ENVCLOAK_TEST_REQUIRE_EMITTERS` (a comma list of `python`, `node`, `go`, `dotnet`, `php` and `serde`) to make a missing one a failure, as CI does. The daemon takes a proof only from a terminal session with no agent in its ancestry (SPEC §10b), so run the tests outside an AI coding agent's process tree: under one, every approval is refused, as it must be. Tests that start daemons run one at a time within each test binary, since Argon2id's memory times parallel vaults can exhaust a runner.

## M2: agent hosts, the scripted model and step S0

M2's gates are end to end with real agent hosts (M2 plan D-13): the pinned Claude Code and Codex binaries, pointed at a local scripted model in an isolated home, run EnvCloak in CI. M2 plan task M2-04 lands the harness, retires the risks it was planned to measure first (K-01, K-02, K-08, K-14, K-21), and runs story step S0. What the hosts were measured to do is in docs/AGENTS.md, "Host behaviour".

### The spike (2026-10-01)

Each tier-1 host was run with its model URL pointed at a recording server and every proxy variable pointed at the same server, which refuses every request meant for a proxy (a `CONNECT` tunnel or an absolute-form request to forward, in HTTP/1.1 or 1.0, with or without `Host`) and records where it was going, so every attempt through the proxy was seen. A direct connection, past the proxy, is neither refused nor recorded by that: in CI the hosts therefore also run with loopback only on both systems (on Linux in a network namespace with nothing but `lo`; on macOS with a group of their own, whose every TCP and UDP packet to anywhere but `lo0` a `pf` rule refuses, and which an access control entry denies the system resolver's socket, `/var/run/mDNSResponder`, since the resolver sends its queries itself, outside the group), so nothing else was reachable there, not even a name server, which a value written into a name looked up would otherwise reach unrecorded. Each agent job checks that, from the test process and from a program it starts (a lookup of `github.com` and a connection to `1.1.1.1:443` both fail, one to a loopback listener succeeds), after checking outside the isolation that the network is open, the same lookup and connection succeeding (`the_network_is_what_ci_says`; `crates/envcloak-e2e/src/network.rs`). On a developer's Mac nothing stops a direct connection or a lookup, and none would be recorded.

### The scripted model

`envcloak-probe-model`, a program of `crates/envcloak-agents` (`probe::model`), never linked into `envcloak` or `envcloakd` (`agent_hosts.rs` checks both binaries for its sentinel). It listens on `127.0.0.1` only, on a port the system picks, refuses a connection from any other address, and answers only requests that present the run's token (`x-api-key` or `Authorization: Bearer`; Claude Code's `HEAD /api/hello` is the one exception). Its HTTP/1.1 parser is hand-written on the standard library: `Content-Length` bodies only, at most 4 MiB a body and 16 MiB recorded in a run, after which the run is `incomplete`; everything outside the grammar is refused with a fixed error that echoes nothing. Every path that records a request (a served or unknown path, a refused token, a request meant for a proxy, the connectivity check) reserves its room first: at most 1,024 records and 1 MiB of what describes them (method, target, header names and values, a forwarded request's whole target, 64 bytes a record), counted from the moment the room is reserved, so connections whose bodies are still being read cannot pass the cap between them; past it the model answers 503, records nothing and the run is `incomplete` (`record_cap`). A request meant for a proxy, a `CONNECT` tunnel or an absolute-form request to forward, in HTTP/1.1 or 1.0 and with or without `Host`, is refused 403 and recorded by the `host:port` it names, with a forwarded request's whole target (path and query included) and its body, read up to the body cap and counted like any other; a request for the model itself is still held to HTTP/1.1 and `Host`. Every record keeps each header's value as well as its name, in wiping buffers, except that a credential presenting the run's token is kept as `<token>`; only a refused token's body is never read (that request fails the run). Each record says whether its reply was sent whole (`answered`); a reply held on a barrier when the run ends was never sent, and the run is `incomplete` (`held_reply`); a reply not sent whole counts as `unanswered`, which a clean run never has. `Debug` shows a reply by its media type and length, a request's target by the endpoint it names or by its length, never the target itself, its method and each header name by name only when it is HTTP's or a known one, else by length, and a barrier by the length of its name. Its test hooks (`admit_as`, `serve_bytes`) exist only with the crate's `testing` feature, which only its own tests enable (`tests/release_features.rs`). It replays a script of turns and tool calls (the step a request gets is the number of tool calls its conversation already holds, so retries get the same step), can hold a step's reply until the test releases it (a barrier, so a person can approve between two turns without timing), records every request body in wiping buffers until the run ends, and has a time limit. Once the run has ended, its last report waits at most 10 s for its reader; then the records are wiped and the program exits 3, so an owner that stopped reading cannot keep it, or what it recorded, alive. It is driven over its standard input and output (`ModelStub`; the testkit's `agents::Model`), never over the network. `qualified()` names the host versions it was run against (M2-28 reads it); a test keeps that table equal to the pinned tier-1 hosts.

Tests: `crates/envcloak-agents/tests/probe_model.rs` (both APIs, the 404, the token, a non-loopback peer, the body, run, record and metadata caps on every recording path and with two connections reserving at once, malformed requests, every form of request meant for a proxy and Python's `urllib` through it, the barrier and an unanswered held reply, the time limit, a last report nobody reads, `Debug`), `tests/probe_http_fuzz.rs` (random bytes and damaged real requests through the connection code: whole responses of known statuses or nothing, no panic, no echo, no recording past any cap). The libFuzzer target over the same entry point (`serve_bytes`) is M2-25's, with the rest of `fuzz/` (review row 37): libfuzzer-sys's `fuzz_target!` expands to `#[no_mangle]` functions, which the workspace's `unsafe_code` rule and `scripts/check-unsafe.sh` refuse outside `envcloak-sys`, and its NCSA licence is not in `deny.toml`; making room for both is that task's decision.

### Pinned hosts

`crates/envcloak-e2e/agents/versions.toml` pins each host: version, install method and the SHA-256 of its entry file on `darwin-arm64` and `linux-x64`, and for a host whose entry is a script its interpreter (`node`: Claude Code's `npm-wrapper` variant and the four npm tier-2 hosts) and the program it starts (Claude Code's and Copilot CLI's platform binaries), hashed too. Node.js itself is pinned there (22.23.3: the SHA-256 of the official archive, as nodejs.org's `SHASUMS256.txt` lists it, of its `bin/node`, and the installer's digest of its whole extracted tree, `tree_sha256`: every path, file and link, its npm included); the installer puts it in the cache beside the hosts, checks a copy already there whole again before using it, and runs every `npm ci` with its own npm only once that run has verified it: when Node fails its check (a changed `bin/node`, npm or any other file, a download or a tree that is not the pinned one), no npm host is installed and nothing is run (review F-100; `install-agent-hosts.py --self-test`, run by `tests/agent_cache.rs` and before every install in CI, with a recording stand-in for `subprocess.run`). The harness runs every node host with it and checks its `bin/node` hash with the host's, so no Node found on `PATH` is ever used (CI's agent jobs set none up). `scripts/install-agent-hosts.py` installs them into a cache outside every HOME (`ENVCLOAK_AGENT_HOSTS`, else `<target>/agent-hosts`, where `<target>` is `CARGO_TARGET_DIR` or the workspace's `target/`: the directory the harness looks in, checked by `crates/envcloak-testkit/tests/agent_cache.rs`), keeping a host only when its download (where pinned) and its entry file hash as pinned. Tests find a host only when its entry file (and the program it starts, and its interpreter) still hash as pinned, and after every run, tier 1 and tier 2 alike, check the hashes again and that `--version`, run in the run's own isolated environment, names the pinned version as a whole word, so a host that updated itself fails the test. Updates are switched off by each host's own setting (`DISABLE_AUTOUPDATER=1`; `check_for_update_on_startup = false`), and Codex runs with `--strict-config`, so a setting it does not know fails the run. npm-installed hosts are installed with `npm ci` from a committed lockfile (`agents/npm/<id>/`), which pins every package in the tree by its integrity hash; install scripts run only where `scripts = true` (Claude Code's `npm` variant, as `npm install -g` runs them).

### The agent home and the sweep

`envcloak-testkit::agents::AgentHome` is a `TestHome` set up for one host: a cleared environment, `ANTHROPIC_BASE_URL` and the run's token for Claude Code, `model_providers.ec` in `$CODEX_HOME/config.toml` with the token in `EC_MODEL_TOKEN` for Codex, every proxy variable at the model, and no developer or CI credential. Claude Code gets `CLAUDE_CODE_TMPDIR` pointed at `claude-tmp/` in the test root, apart from `TMPDIR` (the root's `tmp/`), so a run shows which of the two the host follows: without it, 2.1.280 keeps its per-user temporary directory in `/tmp/claude-<uid>/` whatever `TMPDIR` says, outside the home, and a running command's output lands there, and so does the file its Bash tool has each command's shell write its working directory into (below). A host is started only in a directory inside its test root (one outside it, or a link out of it, is refused). Before each start the harness checks that Claude Code's directory under the shared `/tmp/claude-<uid>/` for that directory and for `HOME` is not there (one that is, such as another run's, a person's own session's, or one for a path whose name collapses to the same, refuses the run), and after the run that it still is not, failing the run if it is, or if a lookup fails other than as "not found" (a directory above it that cannot be searched, say), since that cannot tell. It never removes anything there: that directory is shared with every other run and with the person's own sessions, so what a host kept there stays as evidence (review F-99). Host configuration comes from the hosts' own CLIs where they have one (`claude mcp add-json`, `codex mcp add`); settings a test says the person made are written into the home and labelled so, and Codex's `config.toml` is edited key by key, so what Codex's CLI wrote stays. Every process the harness starts for a host leads a process group of its own: when it exits, or passes its limit, what is left of the group is killed while the leader is unreaped (D-34), and its output is read to the end; output that a process outside the group still holds open fails the run as incomplete, and so does a read of it that fails (never taken for its end). The pseudo-terminal driver for interactive runs does the same for the host it starts in a session of its own, with one cleanup set up as soon as the host is forked and run on every way out of the driver: an exit (seen with `waitid(WNOWAIT)` or a kqueue exit note), a wait that runs out (the screen is written for diagnosis only after it, and a write that fails changes nothing else), a host still running, keys sent to a terminal the host has closed (reported as `GONE <step>` where the write fails, as on macOS; Linux takes them into the terminal's buffer), any signal to the driver whose default action would end it (the harness's `SIGTERM`, a `SIGHUP`, `SIGINT`, `SIGQUIT`, `SIGUSR1`, `SIGUSR2`, `SIGALRM` and the rest: every one is kept blocked and read between waits, so none interrupts or skips the cleanup; the host gets the driver's original mask) and any error in the driver; it kills the host's group, then reaps the host (review F-87; tests with a process that ignores the hangup for each, and one per signal for seven of them). Only a `SIGKILL` to the driver itself, or a signal a fault raises (`SIGSEGV`, `SIGBUS`, `SIGFPE`, `SIGILL`, `SIGTRAP`, `SIGSYS`, `SIGABRT`, `SIGEMT`), skips it. Host flags are pinned per run and never a bypass mode (D-13): Claude Code `-p --permission-mode default` with an explicit `--allowedTools`; Codex `exec --sandbox <mode>` with `approval_policy` set, and `--dangerously-bypass-hook-trust` only in a probe home, where a test says so.

`envcloak-testkit::transcripts` lists every store D-15 names and the ones the pinned versions were seen to write:

| Host | D-15 | Also written by the pinned version |
|---|---|---|
| Claude Code | `~/.claude/projects/**`, `history.jsonl`, `paste-cache/`, `file-history/`, `backups/` | `~/.claude/{sessions,session-env,shell-snapshots,telemetry,todos,debug}/`, `~/.claude.json` and its backups beside it; and, outside `HOME`, `claude-<uid>/<project>/<session>/tasks/<id>.output` in `CLAUDE_CODE_TMPDIR` or `/tmp`: what a Bash command has printed so far, transient (deleted when the command ends; a host stopped half way leaves it; the directories stay); and beside it `claude-<4 hex>-cwd`, which the Bash tool has each command's shell write when it ends (`... && pwd -P >| <file>`): the working directory's path, not what the command printed, removed once the host has read it (store `claude/cwd`, swept like the others; `agent_hosts` asserts where it is and that it is gone) |

A sweep reads each host's directories once, for every canary in every encoding `envcloak-testkit` knows, files each hit under its store and keeps a hit in none of them under `other`: raw counts, nothing filtered, the harness's own canaries included. What it cannot read and that may hold a host file (a root it cannot even look at, such as one below a directory that cannot be searched, a directory above a store, a store, a file) is reported as unreadable, never skipped as if it were not there, and S0 fails on any (review, and review F-88); an unreadable directory beside the host's files in `HOME` is the whole-home sweep's. The scripted model's requests are swept too: each body, and each request's method, target (path and query, or the `host:port` of a tunnel or a request to forward), header names and values, and a forwarded request's whole target, since a host, or a command through the proxy variables that point at the model, can put a value in a request line or a header as well as in a body (`the_model_s_request_lines_are_swept`, with a control for each part). Every sweep (of a store, a body or the whole home) also reads its bytes with one, two, three and four levels of JSON string escaping undone, and counts an occurrence at a level only where it covers a character that level's escapes made: a host keeps what a command printed as a JSON string, Codex keeps a command's result as a JSON string holding JSON, and a value with a quote, a backslash or a non-ASCII character in it, escaped again, matches none of its listed encodings as stored. The negative controls and S0 also sweep the whole test home; the other host tests sweep the host's stores and the model's requests. Positive control: a canary a scripted turn prints with plain `printf`, named in the command in two pieces so only the printed output holds it whole, is found in the tool result the host sent its model and in the host's transcript store; a control a Claude Code command prints while it waits on a barrier file is found in `claude/tmp` meanwhile (and nowhere under `/tmp/claude-<uid>/`); negative control: a run that never saw a canary leaves none anywhere. `crates/envcloak-testkit/tests/transcripts.rs` plants every canary in all 131 encodings the sweep lists in every file of every store, and checks each case alone (that store, that file, that canary, that encoding, at the offset planted), and each case again printed alone inside each envelope a pinned host writes (a Claude Code tool result, a Codex command result, a line Python's `json.dumps` wrote, an Anthropic Messages body and an OpenAI Responses body), found under its own encoding name; the planted bytes come from independent encoders (the `base64` and `form_urlencoded` crates, `format!`, Python's `urllib.parse` and `json.dumps`, `serde_json`, and for the JSON escaping styles no tool here writes, an escaper anchored to those two: the weaker oracle).

### Step S0

`crates/envcloak-e2e/tests/m2_story/skeleton.rs` (the `m2_story` target, one module per task; M2-26 composes the story): the M1 fixture repo `acme-web` is imported by the person; a host, driven by the scripted model with its flags pinned, runs `envcloak run -- ./emit --quick` through its shell tool twice, each invocation printing a nonce of its own first (named in two pieces), so its result is told from the other's and from anything earlier in the conversation. Four cases, one test each: Claude Code with its sandbox off (`s0_claude_code_runs_envcloak_and_the_person_approves`); Claude Code with its sandbox on (`s0_claude_code_sandboxed`: on macOS with the allowance M2-08 writes there, `allowUnixSockets` naming the socket's resolved path; on Linux with none); Claude Code with its sandbox on and no allowance on either system (`s0_claude_code_sandboxed_without_an_allowance`, so the refusal story also runs on macOS, where it is a setting without M2-08's allowance rather than an unsupported one); Codex in `workspace-write` (`s0_codex_workspace_write`: on macOS with the person's settings of §4, command networking on, the network proxy on with no domain rule, one `unix_sockets` rule for EnvCloak's socket; on Linux with no network setting, as M2-08 writes none there). What each case expects is K-01's table (`envcloak_e2e::k01`), the one `agent_hosts` asserts its sandbox measurements against and docs/AGENTS.md records.

Where the table says the shell reaches the daemon, the positive story: the daemon answers `approval_required`, which the host sends its model; the person approves from a terminal of their own, the statement naming the host; the model's next turn, held by a barrier until then, reruns the command, which exits 0 with every serializer listed, both frames of every result the oracle made, a digest per serializer and variable equal to the SHA-256 of the fixture's value (what the command received, checked independently of the redactor) and a redaction marker for every binding. The process the grant is rooted at must be the host the test started, that very process: its pid (unreaped, so not reused), its start time as the kernel reports it, and the pinned entry as its executable. A statement whose root is missing, malformed, another process or another instance fails the step.

Where the table says the sandbox blocks the socket (`unsupported (sandbox_blocks_socket)`, docs/AGENTS.md "K-01 on Linux": both pinned hosts on Linux), the refusal, reported as such and never as a delivery: each invocation's own tool result must be the table's refusal and nothing else. For the CLI that is its nonce once, exactly one line `envcloak: daemon_unverified: the daemon's runtime directory cannot be accessed; nothing was sent to it` and exit 125; for Claude Code's sandbox inside CI's user namespace, which cannot apply its seccomp filter there, it is the sandbox's own `apply-seccomp: write /proc/self/uid_map: Operation not permitted` with no nonce, no `envcloak:` line and no exit at all, since no command ran. A `daemon_unavailable`, another `daemon_unverified` message, another invocation's result or any trace of a delivery (a frame, a digest, a redaction marker) fails the step. Before the host starts and after each refusal the daemon must still be the process the harness started and answer `envcloak status` from outside the sandbox with the environment the host's commands get, so the refusal is the sandbox's and not a daemon that stopped or a directory that is gone; its audit log gains no request; and docs/AGENTS.md must record the same refusal and `unsupported` for the host. The run prints a `receipt:` line saying which it was. Where the sandbox ran no command (Claude Code's inside CI's user namespace), the socket was never tried: that is an environment limitation, not the refusal, and its receipt says so and gives no `sandbox_blocks_socket`; K-01's receipt for that setting rests on the same cases run outside a user namespace, required steps of the `gates`, `agents-e2e` and release jobs, each under its own condition, naming only tests `m2_story` has, and failing unless all it names ran and passed (`--exact` runs nothing for a name no test has; `ci_runs_the_sandboxed_cases_outside_a_user_namespace_as_required_steps` checks the workflow). A delivered run must also add a request to the daemon's audit, so the count the refusal compares is seen to count. In every case every capture, every daemon log, the whole home, every host store and every model request are swept, with a positive control the same session printed (in two pieces) found in the tool result the host sent its model and in the host's transcript.

### CI

`.github/workflows/ci.yml` carries the M2 trigger table (M2 plan §6). A `changes` job reads a pull request's paths through `scripts/ci-paths.py`, which first checks its own table of representative paths (`--self-test`). `gates` (pull requests, Linux) runs the `m2_story` target with the pinned tier-1 hosts restored from a cache keyed by `crates/envcloak-e2e/agents/**` and the installer, for any change to a crate, the workspace manifests, the pins or the workflow; `agents-e2e` runs `agent_hosts` on Linux for pull requests touching `envcloak-agents`, `envcloak-mcp`, `integrations/` or the harness (the e2e crate, the testkit, the manifests, the installer, the workflow), and `agent_hosts` with `m2_story` on both systems for main, nightly and manual runs. On Linux both run under `unshare --user --map-root-user --net` with loopback only (both install Claude Code's sandbox dependencies, bubblewrap and socat, first), and the two sandbox measurements and S0's two sandboxed cases run again outside a user namespace (root makes a loopback-only network namespace and the tests run in it as the runner's user), where Claude Code's seccomp helper can start. On macOS the job makes a group (`ecnonet`, gid 4242) and loads one `pf` anchor that passes `lo0` and refuses every TCP and UDP packet a socket of that group sends anywhere else, then runs the tests as the runner's user with that group alone; the runner's own traffic is untouched. Each job checks the network outside the isolation (open) and inside it (loopback only), from the test process and a program it starts (`ENVCLOAK_TEST_NETWORK`, `the_network_is_what_ci_says` in both `agent_hosts` and `m2_story`). Both jobs run every process at `RUST_LOG=trace` and `RUST_BACKTRACE=full` (gate 12 on the hosts' paths: `TestHome` passes both on, so the hosts and the `envcloak run` they start get them, and the tests sweep what they capture). The release job (main, nightly and manual, both systems) also installs the pinned tier-1 hosts and runs `m2_story` on the release binaries (`ENVCLOAK_E2E_BIN_DIR` at `target/release`) with the hosts required, at trace, loopback only as above, S0's sandboxed cases again outside a user namespace on Linux (`ci_runs_the_hosts_at_trace_and_s0_on_the_release_binaries` checks the workflow). The installer's self-test runs before every install. Runs other than a pull request's each get a concurrency group of their own, so a main run is never cancelled, nor replaced while it waits, by the next merge or the nightly run; pull-request runs cancel their predecessors. `release-check-models` (nightly and manual) is defined with its low-limit keys from Actions secrets; it runs only once the repository variable `ENVCLOAK_RELEASE_CHECK_MODELS` is `on` (when the M2 instruction block exists, M2-08, V1, and the keys are configured), so until then every run shows it skipped, never passed, and once on, missing keys or a missing prompt set fail it.

### Running it locally

`python3 scripts/install-agent-hosts.py --tier 1` (or `--tier all`; it installs the pinned Node.js into the cache first and uses its npm), then `cargo test -p envcloak-e2e --test agent_hosts --test m2_story`, outside an AI coding agent's process tree (S0's approval is refused inside one, as it must be). The tests look in the installer's default cache. When no host was ever installed (no cache directory), each host test skips with a line on standard error; once the cache exists, a pinned host missing from it fails its test, and `ENVCLOAK_TEST_REQUIRE_AGENT_HOSTS=1` makes any missing host a failure, as in CI. `ENVCLOAK_TEST_WRITE_FIXTURES=1` rewrites the hook payload fixtures, for a maintainer pinning a new version. `ec-model --script FILE [--record FILE] [--limit SECONDS] [--keep-home] -- COMMAND` runs any command against a scripted model, for a measurement by hand: in a test home of its own (`/tmp/ecXXXXXX`), with a cleared environment that holds only that home's variables, `CODEX_HOME` and `CLAUDE_CODE_TMPDIR` inside it, and `EC_MODEL_BASE_URL` and `EC_MODEL_TOKEN`, so no credential or configuration of whoever runs it reaches the command. The command leads a process group of its own with an empty standard input, for at most `--limit` seconds (300, the default and the most); past them its group is stopped, and when it ends whatever is left of its group is killed before the home is removed; a descendant that left the group and still holds its output 10 s later is reported, as is a read of the output that fails, and the run exits 3. Its standard error names an endpoint the model serves, an HTTP method and a destination the pinned hosts were measured reaching for (a fixed list: a name's syntax cannot show that it holds no value), and shows anything else a request line held by its length only. The `--record` file keeps them whole (a body, the header values and a forwarded target as the bytes came, in base64): it must be a new path (one already there, a link included, is refused before the command runs), made with mode 0600. A machine with Claude Code managed settings (`/Library/Application Support/ClaudeCode/` on macOS) applies them to the pinned host too; CI has none.
