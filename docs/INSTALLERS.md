# Agent installers and the hook handler

Status: M2 (task M2-08). This file fixes what `envcloak agents install` writes for Claude Code and Codex, how it changes an agent's files, how `envcloak agents uninstall` takes it out, and what `envcloak hook`, the handler the hosts' hooks run, decides. The code is in `crates/envcloak-agents` (`install.rs`, `hosts/`, `writer.rs`, `hunks.rs`, `jsonedit.rs`, `blocks.rs`, `detect.rs`, `locations.rs`, `hook/`), `crates/envcloak-cli/src/cmd/{agents,hook,init}.rs` and `integrations/`. Coverage reporting (`envcloak agents status`, below, "Coverage") is M2-09 (`crates/envcloak-agents/src/{coverage.rs,probe/}`, `crates/envcloak-cli/src/cmd/agents.rs`), and probes on the person's own machine M2-28; the other hosts' installers are M2-24; `migrate-mcp` is M2-20.

Installed is not protected (SPEC §7.1). Everything here prevents accidents: an agent with the person's shell can switch hooks off, edit these files or run a program the hook does not read. Enforcement is the approval proof, the grants and the manifest (SPEC §7.2 rule 4, §10).

## Commands

- `envcloak agents install [--global] [--project] [--agent claude-code|codex]... [--consent-sandbox-sockets] [--yes] [--json]`. Without `--yes` it lists every file and every change, and writes nothing. With it, the daemon must be running and unlocked, since every file is backed up before it changes. Each tier-1 host found on `PATH` is taught (or only those named with `--agent`, whose absence is then a failure). `--global` is the default; `--project` writes the instruction block into the project's own instruction file instead (below), and with both, both.
- `envcloak agents uninstall [--global] [--project] [--agent ID]... [--yes] [--json]` takes out what `install` added (below). Without `--yes` it lists it.
- `envcloak init --agents-note` writes the project's instruction block as `agents install --project --yes` does (SPEC §6.4 step 4); not in a dry run of `--import`.
- `envcloak agents status [--json]` reports each host's coverage ("Coverage", below), exit 0. Before it, a double install (below) is refused with `double_install` and exit 1, naming the files on both sides. `--probe`, which runs the probes on this machine in a probe home of their own, is M2-28's: exit 125, `not_in_this_build`.
- `envcloak hook --host claude-code|codex --event UserPromptSubmit|PreToolUse|SessionStart`, which the hosts run.

Exit 0 when every change was made or was there already; otherwise 1 with `agents_incomplete`, after the report's line for each file left as it was says why. A host that is not installed is reported, and fails the run only when named with `--agent`.

## Hosts are detected, never assumed

A host is the executable of its name on `PATH` (`claude`, `codex`) asked for its `--version` with a cleared environment (`HOME`, `PATH` and the host's own location variable) and a 5-second limit, which covers reading its output too: a process it leaves behind holding the output open ends the wait at the limit, as `version_timeout`. The answer is read strictly: Claude Code's `<version> (Claude Code)`, Codex's `codex-cli <version>`, the version three runs of digits with an optional pre-release. Any other answer is `not_recognized`, and nothing is written for that host (SPEC §7.2 rule 1).

**Why `.claude.json` is edited, not changed through `claude mcp`.** The M2 plan (D-16) had the server registered with `claude mcp add-json` and removed with `claude mcp remove`, never editing the file. Codex's review found that those commands rewrite the file after EnvCloak has read and backed it up, with nothing binding the rewrite to what was read, so a save another program made in between (Claude Code itself, which rewrites the file as it runs) was changed or lost unchecked, and the backup did not hold what the command changed. The entry is therefore written by EnvCloak's writer, like `settings.json`: read beneath its directory, backed up, edited span by span (every other byte kept), and replaced only while it is still the file read, its stamp checked at the rename; under D-16's rules for a file the host rewrites, so Claude Code has to be closed (2 minutes since its last write, open in no other program), unless the file's stamp is still EnvCloak's own. No `claude mcp` command is run. Measured with the pinned 2.1.280 (`m2_story`): Claude Code lists the server from the edited file, install then uninstall gives the file back byte for byte, and `claude mcp list` rewrites a file without its start-up fields, which then keeps Claude Code's state when EnvCloak's entry is taken out.

An MCP server named `envcloak` that the person registered themselves stays theirs, even with EnvCloak's very settings: install changes nothing and says so (`mcp_server_yours`), and uninstall leaves it; one with other settings is a conflict, refused. EnvCloak's entry is its own only while it holds what EnvCloak wrote (the person's edit makes it theirs), and only in the file it was written in (the state keys each file by its path, its directories resolved): after `CLAUDE_CONFIG_DIR` moves, an equal entry in the new directory's file is the person's, and uninstall takes EnvCloak's out of the file it wrote it in. When EnvCloak created `.claude.json` (a fresh home), uninstall removes a file still exactly as it left it, and one Claude Code has written its own state into since keeps everything but EnvCloak's entry.

### The project scope

`--project` (and `init --agents-note`, for both hosts) writes the instruction block into the project's own files, one for each host asked for (every tier-1 host, or those named with `--agent`), chosen by that host's own precedence (Map C sections 2 and 6; Codex review: one file for every host missed Codex beside a lone `CLAUDE.md`, and wrote an `AGENTS.md` that an `AGENTS.override.md` shadows):

- Codex reads one file in a directory: `AGENTS.override.md`, else `AGENTS.md`, else the first of `project_doc_fallback_filenames` that is a file there; with none of them, a new `AGENTS.md`. The list is the one Codex's merge of its layers leaves for a session in the project's directory (`envcloak_agents::codex_layers`, from the pinned 0.159.2's loader): `/etc/codex/config.toml`, then `~/.codex/config.toml`, then each `.codex/config.toml` from the project root down to the directory, then `/etc/codex/managed_config.toml`, a higher layer's list replacing a lower one's, an empty list included (Codex's round 6 review: the installer had joined the user's list and the project's, so with both lists' files there it wrote the user's while Codex read the project's; measured on the pinned Codex in `m2_story`). A file read under a fallback name that is not one of the agent files EnvCloak's backups hold (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md` and the others docs/IPC.md lists) cannot be backed up, so the block is not written there (`backup_failed`, the run incomplete). With an `AGENTS.override.md` nothing is written for Codex (EnvCloak never writes into an override), and the report says so (`project_override_file`).
- Claude Code reads `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md`, the first there; with none, `AGENTS.md`, which it reads from 2.1.277 while no such file is in the project or above it (`claude_reads_agents_md`). One above it (a parent's `CLAUDE.md`, other than the person's own `~/.claude/CLAUDE.md`) means no project block for Claude Code, said so (`claude_reads_above`). It never creates a `CLAUDE.md` or `CLAUDE.local.md` beside a lone `AGENTS.md`.

A file both read gets one block. The project is the directory of the nearest `envcloak.toml`, else the working directory. What a plan read of these files is read again when the block is written (lesson L-09): an override that appeared since refuses the write (`override_file`), and the sizes of the files Codex reads first are taken then.

**Codex's budget.** Codex reads only the first `project_doc_max_bytes` (32 KiB unless its merged layers say otherwise; for `~/.codex/AGENTS.md`, the smallest of 32 KiB and every value of the system, user and managed files) of the instruction files it joins, the files from the project root down coming first; the root is the nearest directory at or above the session's that holds one of `project_root_markers` (from the layers below the projects', `.git` when unset; an empty list: the session's directory alone; Codex's round 6 review: the installer knew `.git` only, measured on the pinned Codex with `.hg`) (Codex review: a block appended to a longer file was never read, and install said complete). A block in a file Codex reads ends within that budget: appended when it fits there, else put at the top of the file (an existing block past the budget is moved there); when the files read before it leave no room, or the size of one of them cannot be read, it is not written (`instruction_budget`, the run incomplete). `~/.codex/AGENTS.md` is held to the same budget. The settings, the file Codex reads and the files before it are read again when the block is written: a project whose settings now make Codex read another file refuses the block (`instruction_file_moved`). The settings are those of a session started in the project's directory, as Codex reads them once the project is trusted (Codex reads no project instructions in a project it does not trust).

## The instruction block

The same bytes in every file (so hosts that read several can tell the copies are one), between the lines `<!-- envcloak:begin -->` and `<!-- envcloak:end -->`, which Claude Code strips from context; the instructions are never inside an HTML comment. Its text (`envcloak_agents::blocks::INSTRUCTIONS`) names only commands this build ships (`run`, `ls`, `ref`, `add`, `init`) and never `--ask`, which comes with the app (M3; D-20). It is worded for any agent: it never says a hook will stop anything, since some hosts that read these files run no hook.

A file is refused, and reported, when it is not UTF-8, when its markers are repeated, unpaired, out of order or not lines of their own, and when the block would be inside an open HTML comment or code fence (hidden there): a file that ends inside one, or a block already there inside one, even one exactly as it should be (`inside_comment`). A fence closes only with its own character (backticks or tildes), at least as many of them and nothing after but white space, as CommonMark reads it. A block of an earlier EnvCloak version is replaced in place; a block whose text between the markers is not one EnvCloak wrote (the person edited it) is neither replaced by install nor taken out by uninstall (`block_modified`): that text may be theirs.

## How a file is changed

`envcloak_agents::writer` (lesson L-11):

1. The file is read beneath its directory, never through a symlink. A symlink, a file with another hard link, one that is not a regular file of this user, and one over 1 MiB (64 MiB for Claude Code's `.claude.json`) are refused and reported, never changed; so is a change, or an undo, that would make a file larger than that (`too_large`), which could then be neither changed again nor taken out: refused before anything is backed up, saved or written, the record kept, so a later uninstall makes the undo once the person has made room (Codex F124).
2. JSON is read strictly (RFC 8259): comments and trailing commas (JSONC) are refused and named, as are a key given twice in one object, a byte-order mark, invalid UTF-8, a lone surrogate, control characters in strings and nesting past 64. Edits change only the spans they add to: every other byte stays, in a file laid out on lines the new entry goes on a line of its own at its siblings' indentation, in a one-line file on that line. TOML is edited key by key with `toml_edit`, which keeps the rest of the file as it was; a key given twice is refused. An MCP server named `envcloak` that EnvCloak did not write is a conflict, refused.
3. **D-16.** A file the host rewrites itself (Claude Code's `settings.json` and `.claude.json`, Codex's `config.toml`) is changed only while no other process has it open and when it was not modified in the last 2 minutes: quit the agent and run again. A file whose stamp (device, inode, size, modification and change times, mode, links, owner) is still the one EnvCloak recorded right after its own last write, an uninstall's included, is not held to the 2 minutes, so `agents install` and an EnvCloak edit of the same file right after it (`agents install` again, `uninstall`, `migrate-mcp`, and `install` right after `uninstall`) work without waiting or backdating. A change by the host or the person in between makes the stamp another, and the 2 minutes apply again.
4. An existing file is backed up first, as a backup v2 the daemon seals with purpose `agents` (docs/IPC.md "Backups v2"); without the backup nothing changes. After the change its result, the SHA-256 of what the change left, is recorded. A file the installer creates (Codex's `hooks.json` and rules file, a new `AGENTS.md`, `~/.claude.json` in a fresh home) has nothing to back up, and so no daemon record of its creation: only EnvCloak's state names it, and `agents uninstall` removes it. The audit record of every agent configuration change, creations and removals included (docs/VAULT.md audit kind 27, `agents_config`), needs a daemon handler, which is lane A's, and is requested there.
5. The file is replaced in one step only if it is still the file read (`envcloak_scan::replace_atomically`, the stamp checked again, change time included); a new file is created only if its name is still free (mode 0600). The new contents are written beside the file under a temporary name first (SPEC §6.5 "Modifying a file"), and the old ones are under one for a moment after the swap; the SHA-256 of both is saved before the write (`State::leftovers`), so files of those names left by a run that was stopped, or by a write that could not remove one, are removed by the next `agents install` or `uninstall`: only a regular file of the person's with no other link, of the temporary names' shape (`.<name>.envcloak-<new|swap|del>-<hex>.tmp`), holding exactly those contents, or, under the name new contents are written under, their first bytes (a write stopped part way, which can already hold a literal key; the state keeps no text, so the run that works out the same contents again, the next install or uninstall of the file, is the one that removes it), nothing included. A file of that shape not shown to be EnvCloak's stays, and so does the record: the report names it (`Left beside a config: ...`, `leftovers` in `--json`) and the run exits 1 until it is gone. A directory that cannot be listed is not read as empty (Codex F123): the record stays, the report names the directory apart from the files (`Cleanup not confirmed: ...`, `cleanup_unconfirmed` in `--json`; a place to look, never a file to remove) and the run exits 1 until it can be listed; so does a directory install made that uninstall could not remove. A save of `state.json` stopped part way is removed the next time the state is opened (its directory is EnvCloak's own, and the state holds no text of the person's files). A failure the file system reports once the change was made (the old file left under a temporary name, a sync) is reported with the change made, naming the file left behind, never as a refusal: what the file holds says whether the change was made.
6. The change's record is saved in `<data>/agents/state.json` (0600, its directory 0700, locked while an install or uninstall runs; format 2, and format 1, which earlier builds of this change wrote with Claude Code's MCP registrations kept apart, is read and each registration made the record of its `.claude.json`, so the installation it records is still managed: Codex F-125) before the file is written, marked as an intent, and confirmed with the new stamp once it is. A run stopped in between is settled by the next one from the file's SHA-256: the change was made (EnvCloak owns it), was not (the record before it comes back), or the file changed since (its edits are taken out by structure only). A failure after the file changed (the state cannot be saved, the backup's result cannot be recorded) is reported with the file as `changed` and the reason, and the run exits 1: never as a success, and never as a refusal of a change that was made.
7. The state holds no text of the person's files (it sits outside the vault and its sealed backups, and a config can hold a literal key next to what EnvCloak edits): SHA-256 digests, stamps, EnvCloak's own edits (a block, an array element of its own, a TOML key with what it held before, which is only ever a boolean, `allow` or `deny`: anything else there is refused, never written over), and, for each change, where its inserted text went and how long it is (`envcloak_agents::hunks`), with the white space it replaced. A change that replaced anything else (a TOML value set over another, an older block) keeps no such entry and is undone by structure.

A reinstall makes the files hold what this run writes: what an earlier install wrote and this one does not (Claude Code's hooks once the plugin is enabled, a socket or data path that moved, the hooks of an earlier EnvCloak path, Codex's socket allowance) is taken out by structure while it still holds what EnvCloak wrote, and EnvCloak's record of it goes (lesson L-09).

## How uninstall takes it out

For each file the state names for the hosts and scopes given:

- still byte for byte what EnvCloak last left (its SHA-256): each change's inserted text is taken out in reverse, which gives back the file as it was before the first install, byte for byte, its SHA-256 checked; a file EnvCloak created is removed;
- changed since (the host rewrote it, the person edited it), or changed by EnvCloak in a way it undoes by structure: only EnvCloak's edits are taken out, by structure (the block; the array elements equal to the ones added, and the objects and arrays the install created once they are empty; the TOML keys still holding what EnvCloak wrote, set back to what they held before or removed); a file EnvCloak created that holds nothing else is removed;
- a file that is EnvCloak's whole (Codex's rules) is removed only while it is exactly what EnvCloak wrote; changed since, it is left and reported (`modified`), and install does not replace it either;
- the directories install made for the files it created (`~/.codex/rules`, a `~/.codex` that was not there) are removed once empty, innermost first; one that holds a file of the person's by then stays theirs;
- a project's file (`--project`) is taken out only once no host its block was installed for is left: EnvCloak's record of it keeps those hosts, so `agents uninstall --project --agent codex` leaves a block Claude Code was installed to read (a lone `AGENTS.md` both read, or a file installed for both), says so (`keep EnvCloak's block, which it was installed for Claude Code to read too`, and in the dry run's JSON `kept_for`), and takes it out with Claude Code's uninstall (Codex review, round 7: every block of the project was taken out). A record from before the hosts were kept counts every host. The project's directories EnvCloak made go with the last of its files there.

The same D-16 rule, backup and atomic replacement apply, to `.claude.json` as to every file: its `mcpServers.envcloak` is taken out of each `.claude.json` EnvCloak wrote it in, while it holds what EnvCloak wrote, and the `mcpServers` object install made goes once empty. A file whose last write was EnvCloak's own keeps that stamp known when uninstall finds nothing of EnvCloak's left in it, so an install right after is not held to the 2 minutes.

## The hook handler

`envcloak hook` reads the payload from standard input into wiped storage, at most 2 MiB, and answers within 2 seconds of its start: the deadline covers the decision too (it runs on a thread of its own, and one not ready by then is `unchecked`), and here-documents are matched to their commands once each, so a payload of thousands is read in one pass. The parsed payload's strings, the prompt check's copies and the command reader's words and here-document bodies are wiped when dropped; serde_json's own scratch buffer for strings with escapes is not. Decisions are pure functions of the payload (`envcloak_agents::hook::decide`, D-12): the same payload always gets the same answer, so a hook a host fires twice (natively and through another host's import) agrees with itself. Nothing is compared with the vault and nothing is sent anywhere.

| Event | Decision |
|---|---|
| `UserPromptSubmit` | stop the prompt when, as written or with the `<pasted_content id="…">` lines around pastes taken out (so a key pasted in two parts is read whole), it holds a word a provider's key pattern matches, a URL with a password, or a run of 24 or more ASCII letters and digits that holds both, other than one of exactly 40 or 64 hexadecimal digits in one case (a commit or a digest) |
| `PreToolUse` | stop a shell command (`Bash`, and Claude Code's `Monitor`, whose `command` is a shell script) that reads an env file, prints the environment, or runs `envcloak reveal` or `envcloak approve`, and one whose commands cannot be told (below); ask about one whose reads are not resolved (below: Claude Code asks the person, Codex stops it); Claude Code's `Read`, `Edit` and `NotebookEdit` of an env file or of a process's environment (`/proc/<pid>/environ`), and its `Grep` of one (by `path`; by a `type` whose globs hold env files: `sh`, whose globs include `.env` from ripgrep 15 on (14.1.0's do not), and `all`; or by a `glob` that may pick one out, below); an MCP tool call, a `ReadMcpResourceTool` or `ReadMcpResourceDirTool` read, and an `Artifact`, `Projects`, `Workflow` or `ClaudeDesign` call, any of whose string arguments names an env file or a process's environment (a `file://` URI included); and `mcp__envcloak__run_with_secrets` with an argv in those classes. A command run through `envcloak run [options] -- <command>` is read as the command it runs. A search's options that pick the files it reads are read as such: ripgrep's `--glob`, `--iglob`, `--type` and `--type-add`, grep's `--include`, ag's `-G`, and find's `-name`, `-path` and `-regex` (whose wildcards match a leading `.`). Names are read in one case (macOS's file system opens `.ENV` as `.env` and finds `CAT` as `cat`). `Glob` lists names only and is let through |
| `SessionStart` | add, as context, the names (never the values) of the variables the session directory's `envcloak.toml` binds, from the daemon, and the one-line usage rule; nothing when there is no manifest or the daemon does not answer in time |

An env file is one `envcloak_scan::dotenv_kind` names (`.env`, `.env.<profile>`, and a `.env.` suffix it cannot read); templates (`.env.example` and the like) hold names only and are not. Reading the shell command: see `crates/envcloak-agents/src/hook/shell.rs` for the grammar read, POSIX shell's with bash's and zsh's additions (Claude Code's Bash tool runs zsh on macOS, docs/AGENTS.md): zsh's `=name` runs `name`, its precommand modifiers (`noglob`, `nocorrect`, `-`) and `repeat`, `coproc`, `typeset -m`, `declare -m` and `export -m` (which print the parameters a pattern matches, values included), brace sequences as the words they make (zsh's `{....}` is `.`), and POSIX bracket expressions (`[[:alpha:]]`, `[[=e=]]`, `[[.e.]]`), read as a class that may stand for any character. A command whose structure cannot be told is stopped too (`ambiguous`): an unfinished quote or substitution, a command named by a variable (`$CMD`, `c${IFS}at`), `eval` or `sh -c` of text only known when it runs, or nesting past 24.

**Fail closed** (the orchestrator's finding: the reader had listed bad forms, and a review could always find another). A command that reads files or the environment is let through only when what it reads is resolved; otherwise it is `unresolved`, never allowed: Claude Code gets `permissionDecision: "ask"` (the person sees the reason and decides; a non-interactive session cannot answer, and the command does not run, measured with 2.1.280 in `m2_story`), and Codex a denial, since Codex runs a call its hook asks about (Codex's cycle178 measurement); the MCP server refuses it. Unresolved: a reader's file, a redirection's input or a `source` whose name is only known when it runs (`cat "$f"`, `cat $(...)`, `< "$f"`, `"$d"/environ`) or is zsh's `=name`; a reader's glob when anything in the script changes how globs are read (bash's `shopt`, zsh's `setopt`, `unsetopt` and `emulate`, `set -o` with an option other than bash's, `set` with a flag outside bash's, `GLOBIGNORE`, `BASHOPTS` or `SHELLOPTS`, a shell started with `-O` or `-o`), since the shells' leading-dot rule the reader relies on may not hold then; a program the reader does not know, one of whose words is a command it does know that would read an env file or print the environment (`firejail cat .env`, `dbus-run-session printenv`: the program may run it). A program the reader does not know is not taken to read nothing: it is asked about when it is given an env file's name, in a word or in a word's text (`iconv -f utf-8 -t utf-8 .env`, `cp .env /dev/stdout`, `curl file:///w/.env`, `--env-file=.env`, `HEAD:.env`, `-d @.env`, `su -c 'cat .env'`, `python3 -c 'print(open(".env").read())'`, an interpreter's here-document; a copy's destination is written, not read, and git's commands that print no file, `git rm --cached .env` or `git commit -m "ignore .env"`, are let be, but not git given `-c` or a message file); when a word of shell text it is given holds a class (`su -c 'env | sort'`, `ssh host 'printenv'`); when it is an interpreter whose code names the whole environment (`os.environ`, `process.env`, `%ENV`, Ruby's `ENV`) or a process's (`/proc/self/environ`); when it is given a glob under changed glob options (`setopt globdots; tar cf - * | tar xOf -`); and when the script spells an env file's name anywhere (a word, a `for` list, a `case` pattern, a here-string) and a value only known when it runs may carry it to such a program (`for f in .env; do cp "$f" /dev/stdout; done`, `echo .env | xargs cat`, `printf 'cat .env' | sh`). A variable, an exported one included, given an env file's name is asked about too (`x=.env`, `ENV_FILE=.env.local npm start`). Runners' own options are read as a program's (`uv run --env-file .env`, `bun --env-file=.env`). A reader's own program is read for what it reads and runs (Codex's round 6 review: it was taken as a pattern): sed's `r` and `R` read the file they name and `e` and `s///e` run a command (the script parsed as GNU and BSD sed parse it, `sed -i '' ...` included); awk's `getline < FILE` reads FILE, and a pipe, `system`, `ARGV`, `ARGC`, gawk's `@` forms and `ENVIRON` other than `ENVIRON["NAME"]` are asked about; jq's and yq's `env` and `$ENV` other than one variable by name, `import`, `include`, yq's `envsubst` are asked about, and yq's `load("FILE")` reads FILE; a program given in a file (`sed -f`, `awk -f`, `jq -f`), code a program loads (gawk's `-i`, `-l`) and a program with a stretch only known when it runs (`sed "1r $f"`) are asked about; a pager or preprocessor a reader runs (`rg --pre`, `bat --pager`, `sort --compress-program`, `sdiff --diff-program`) is read as a command. A pattern given in a file (`grep -f`, `rg -f`) leaves every operand a file read. `export -p NAME`, `readonly -p NAME` and `typeset -p NAME` print the variable's value (zsh; dash's `export -p NAME` prints every exported variable), and are stopped as `env_dump`. A program known to take its words as data (`echo`, `which`, `man`, `ls`, `rm` and the others in `shell.rs`'s `inert`) is not read that way, nor is a bare `env`, `set`, `export` or `declare` as the last word (`python -m venv env`). Text that names an env file given to such a program is asked about even when it is a message (`gh pr create --body "... .env ..."`): the message can be written to a file and passed by name. What stays let through is listed below, each class with its examples. `crates/envcloak-agents/tests/shell_oracle.rs` checks the property against the shells themselves: random spellings of reading `.env`, `sub/.env` and `/proc/self/environ` and of printing the environment, run by bash, sh, dash, zsh and bash 5 (and by find and grep with their own globs) in a directory whose env files hold a canary; every spelling that reaches the canary in any shell must be stopped or asked about.

**Answers.** Allowed: no output, exit 0. Asked about (Claude Code, `unresolved`): `hookSpecificOutput.permissionDecision: "ask"` with the reason on standard output, exit 0. Stopped: the host's JSON on standard output (Claude Code: `decision: "block"` with `hookSpecificOutput.suppressOriginalPrompt` for a prompt, `permissionDecision: "deny"` for a tool call; Codex: `decision: "block"` for a prompt, `permissionDecision: "deny"` for a tool call), the message on standard error, and exit 2, which stops the action on both hosts even where the JSON is not read. Every message starts with EnvCloak's marker `[envcloak:<reason>]` (`key_in_prompt`, `env_file`, `env_dump`, `reveal`, `approve`, `ambiguous`, `unresolved`, `unchecked`, `traced`), which the probes look for (M2-09), says what to do instead and that the hook prevents accidents; none echoes what it matched. A payload over 2 MiB, not all there within the 2 seconds or not decided within them stops the prompt or the tool call (`unchecked`). Under a debugger or tracer the handler reads nothing, its payload included, which can hold a pasted key (SPEC §5): the prompt or the tool call is stopped (`traced`), and `SessionStart` adds nothing. `agents install` and `uninstall` (and `init`, before `--agents-note`) refuse under a tracer too, with `traced` and exit 1, before they read an agent's config. A payload that is not the one `--host` and `--event` name (another event, another host's shape, a field of the wrong type, not JSON) gets no decision: `envcloak: hook_payload: ...` on standard error and exit 1, which both hosts take as a hook error that stops nothing. A usage error exits 1 too, never 2.

**The same check in the MCP server.** `run_with_secrets` refuses an argv in the classes above, the unresolved one included (it has no one to ask), before it asks the daemon anything, with the hook's message and the token `command_refused` (D-22), so a host without hooks gets the same accident prevention.

**Fails open.** A hook that does not answer within the host's timeout lets the action through on both hosts (Claude Code documents it; Codex was measured, docs/AGENTS.md). Hook-based surfaces therefore read `fails_open_on_timeout` and are never `active` (SPEC §7.1).

**Search globs** (`envcloak_agents::hook::shell::glob`). Claude Code 2.1.280's `Grep` splits its `glob` before ripgrep reads it (on white space, then each piece without both `{` and `}` on commas, each piece one `--glob`, the search `--hidden`), and the hook reads each piece; one that may pick out an env file stops the call. A glob is read in its own language: `*` and `?` match a leading `.`, a character class is the set it stands for (`[.]e[n]v` is `.env`), with ranges, negation and `\` escapes, a class holding a POSIX bracket expression (`[[:alpha:]]`, `[[=e=]]`, `[[.e.]]`) is read as one that may stand for any character, `/` included (the verifier's finding: read as members before), and brace alternatives are expanded. Where its last component starts is read in that language too: a `/` inside a class is one of its members (`[/.]env*` is read whole), and a class that may match a `/` (one that holds it, or a negated one that leaves it in) is read both as a member and as the separator, since ripgrep matches the separator with it (`sub[/].env` and `sub[!a].env` pick out `sub/.env`, measured with ripgrep 15.1.0); find's `-path` and `-wholename` match a `/` with `*` and `?` as well (`find sub -path 'sub*env'`), its `-name` does not; grep's `--include` is read so too, since macOS's grep (BSD 2.6.0) matches it against the whole path, its `*` and `?` across a `/` (the verifier's finding: `--include='./s*v'` reads `sub/.env` there; GNU grep matches the base name, which this covers). Its last component may pick out an env file when it has no wildcard and one of the names it stands for is an env file's (`.env.local`, `[.]e[n]v`); when it starts with literals or classes that can begin an env file's name (`.env*`, `.e?v`, `.*`, `.E*`); or when it starts with a wildcard and an env file's name matches it with a literal or a class, not a wildcard, standing for a character of `.env` itself (`*.env`, `*env*`, `*[e]nv`, `*v`). A glob that starts with a wildcard and whose literals and classes would stand only for what follows `.env` (`*`, or `*.rs`, which a file named `.env.rs` would match), only exclusions (`!...`), and `Grep` with no `glob` are read as a search of every file, the rows above: an env file in that directory is searched unless ripgrep skips it. A regular expression that picks files (find's `-regex`, ag's `-G`) is read as one that may when the letters `e`, `n`, `v` appear in it in that order. `crates/envcloak-agents/tests/grep_glob_oracle.rs` checks these answers against ripgrep itself: which globs pick out which file, with the host's split and files in a subdirectory; which files each of the installed ripgrep's types picks out, asked of ripgrep by name, in both directions (`all` included); and which a type defined with `--type-add` picks out.

The prompt check misses: a key made of words and separators that no provider pattern names (an AWS secret access key on its own), a key of exactly 40 or 64 hexadecimal digits, a URL whose password holds a character a URL must escape (a `/`, a space, a quote) written unescaped, and a key encoded or broken up by other text. Hooks see only what the host passes them: Codex's `write_stdin` into a running session does not rerun `PreToolUse`, hosted tools are not covered, and `@` mentions never reach Claude Code's `PreToolUse` (the `Read(**/.env*)` deny rule covers them, best effort).

## Coverage: `envcloak agents status`

`envcloak agents status [--json]` reports, for each tier-1 host found on `PATH` and its version, six surfaces separately (SPEC §7.1): prompt-to-model, transcript, file read, shell, MCP and output. Each has a state, its reason tokens (sorted, from the one registry in docs/IPC.md) and its probe outcome, kept apart: `degraded (fails_open_on_timeout, workspace_untrusted; probe=passed)`. A failed probe reads `probe=failed` and is listed first, so a reason never hides a broken probe. Then EnvCloak's own MCP server: how the host lets an agent call `run_with_secrets` (`listed`, `callable` when the person approved it in the host's own settings, `needs_host_approval` otherwise: the installer approves no EnvCloak tool, D-22), and always `outside_host_sandbox` with its probe outcome and the sentinel's evidence: `needs_host_approval; outside_host_sandbox (probe=passed, sentinel appeared)`. Copilot CLI, OpenCode and Goose, when on `PATH`, are reported with their prompt guard and the blocked prompt's persistence `unsupported` without a probe (their documentation gives no way to reject a prompt; SPEC §7.1's table), their other surfaces `unverified (not_probed)` until their installers and probes (M2-24); each is told only by the name of an executable on `PATH`, which another program can have (`goose` is also a database migration tool), so the report says it is not identified (`"identified_by": "executable_name"`; a tier-1 host is told by its version line, `"version"`). A case of a surface's probe that was not run while the rest was is named after the outcome, never counted as passed: `degraded (...; probe=passed, at_mention skipped)` (`"skipped": ["at_mention"]` in `--json`). The code is `crates/envcloak-agents/src/coverage.rs` and `src/probe/`.

**States.** `active` only when the surface's probe passed on this machine for this host binary, version and configuration, and nothing degrades it; in this build only output can be, since every hook can time out. `degraded` when the hooks a surface rests on need trust, can be switched off or fail open, with the reasons below (and with `probe=failed` when its probe failed under them). `unsupported` where the host offers no contract: a blocked prompt kept in the host's stores (`persists_blocked_prompt`: the transcript probe found it, or, until a probe ran, Claude Code's own documentation says so), a sandboxed shell no documented allowance lets reach EnvCloak (`sandbox_blocks_socket`, K-01: on Linux for Claude Code with `sandbox.enabled`, and for Codex unless its `sandbox_mode` is `danger-full-access`), or a host with no prompt-rejection contract. `unverified` otherwise: no probe result for this binary, version and configuration (`not_probed`, or `changed_since_probe` when the one kept is for another), EnvCloak's hook for the surface missing or naming a program that is gone (`hook_missing`: such a hook fails open on both hosts), a failed probe nothing explains (`unverified (probe=failed)`), or a probe that could not run (`probe_needs_terminal`).

**What `agents status` reads.** The files each host reads for a session in the working directory `agents status` runs in (never the nearest manifest's: a folder below it can hold settings of its own), as the pinned hosts read them (measured in a scratch home on macOS, each with a hook or server that leaves a mark when it runs): Claude Code 2.1.280 reads the project's `.claude/settings.json` in the working directory only (not a folder above it), `.claude/settings.local.json` there and at the git root above it (the nearest folder holding `.git`), every `.mcp.json` from the working directory up to `/`, the user-scope `mcpServers` of `~/.claude.json` and its local-scope entries (`projects."<folder>"`, read here for the working directory and every folder above it); Codex 0.159.2 runs the hooks of a trusted project's `.codex/hooks.json` from the project root down to the working directory (an untrusted project's do not run), as it reads its config layers. Every level that sets a switch is reported, whatever a higher level sets (a project's `false` does not hide the user's `true`: another project's sessions read it). A settings file that is there but cannot be read as JSON or TOML is taken as switching its level off. `--safe-mode` and `--bare` are command-line flags of a session, which no file shows. **The probes** (`envcloak_agents::probe`; M2 plan M2-09): the real host, its flags pinned per probe, against the scripted model, which records every request (a value is looked for in every part of every request: its method, path, query, header names and values, body and forwarded target; and in the host's stores, in every file's contents and every entry's name). Each probe has a control in the same probe home and session, so a host that never reaches the model fails the probe, never passes it. The prompt probe and its controls run as one session against one scripted model (Codex review of M2-09: as two sessions, a probe run that ended without sending anything read as a block): the control in a session of its own (Claude Code's under an id the probe gives it, `--session-id`), that session found by its control in the host's store (Claude Code's `projects/<folder>/<id>.jsonl`; Codex's one `sessions/**/rollout-*-<id>.jsonl` holding the control), the probe in the same session resumed (`--resume <id>`; `codex exec resume <id>`, which takes the sandbox as `-c sandbox_mode=...` in place of `--sandbox`), and a second control there after it. The host must report the block, as the pinned hosts do (measured): Claude Code prints `UserPromptSubmit operation blocked by hook:` and the hook's reason, EnvCloak's `[envcloak:key_in_prompt]` in it; Codex prints `hook: UserPromptSubmit Blocked` on its standard error, naming no hook, which counts only where no other prompt hook is in a file it reads hooks from. What a host prints is read as it comes for those fixed texts only, and dropped. Neither host sends a prompt it blocked on the session's next turn (measured: the second control's request holds the first control's turn and not the token). A file-read or shell probe's hook case is a call EnvCloak's own host rules leave to the hook, on both hosts, so its marker can only be the hook's and a hook taken out fails it; the call a rule covers is the rule's case, which passes refused by the rule or the hook (one rule for both hosts: Claude Code's `Read(**/.env*)` matches within the session's working directory, Codex's `forbidden` rules match `printenv` and `cat .env` by their prefixes). A refusal in the host's own words counts as the rule's only where it can be no other's (the verifier's round-2 finding): Claude Code's names no rule, so it counts only while the settings hold EnvCloak's `Read(**/.env*)` and no other deny rule for its file tools (else the case fails: "the host refused it under a rule not known to be EnvCloak's"); Codex's carries the justification of EnvCloak's own rule.
